# Timer fixtures

Each `NN-name.json` is one scenario for the timer fold (`docs/protocol.md` §5). Both the Python fold and the TypeScript fold must produce exactly the expected output. **Expected values are written by hand from the rules, never generated by running a fold.**

## Format

```jsonc
{
  "name": "pause-resume",                       // must equal the filename after "NN-"
  "description": "…",
  "session": { "session_id": "sess-1", "duration_ms": 600000, "created_at_ms": 0 },
  "events": [                                   // list order is NOT significant
    { "command_id": "c1", "type": "PERMIT", "actor_kind": "staff",
      "claimed_at_ms": null, "received_at_ms": 1000 },
    { "command_id": "c2", "type": "START", "actor_kind": "room",
      "claimed_at_ms": 5000, "received_at_ms": 5000 },
    { "command_id": "c3", "type": "ADJUST", "actor_kind": "staff",
      "claimed_at_ms": null, "received_at_ms": 70000, "delta_ms": -60000 }
  ],
  "expected": {
    "event_results": [                          // same order as "events"; fold evaluated with all events received
      { "command_id": "c1", "result": "applied",  "reason": null },
      { "command_id": "c9", "result": "rejected", "reason": "not_running" }
    ],
    "at": [                                     // probes: fold only the events with received_at_ms <= now_ms
      { "now_ms": 65000, "remaining_ms": 540000,
        "snapshot": { "status": "RUNNING", "duration_ms": 600000, "adjust_total_ms": 0,
                      "elapsed_banked_ms": 0, "running_since_ms": 5000 } }
    ]
  }
}
```

## Semantics a probe at `now_ms` must follow

1. Keep only events with `received_at_ms <= now_ms` (the server cannot know about later ones).
2. Apply the rules in `docs/protocol.md` §5, including "reaching zero ends the session".
3. Compare `snapshot` and `remaining_ms` exactly.

## Index

| # | Name | What it pins down |
|---|---|---|
| 01 | permit-only | events invisible before they are received |
| 02 | start-and-run | basic countdown |
| 03 | natural-expiry | zero is inclusive; no END event needed |
| 04 | pause-resume | paused time not counted |
| 05 | multiple-pauses | banked time accumulates |
| 06–07 | adjust-plus/minus-running | adjustments on a running timer |
| 08 | adjust-while-paused | adjust doesn't change pause state |
| 09 | adjust-before-start | adjust while PERMITTED |
| 10 | events-listed-out-of-order | fold sorts by effective time; ADJUSTs add |
| 11–12 | adjust-negative-…expiry | adjust that drives remaining ≤ 0 ends the session |
| 13–14 | early-end-… | staff END freezes remaining time |
| 15–17 | …-rejected | invalid transitions are rejected, not dropped |
| 18 | offline-start-vs-staff-start-on-behalf | late offline event re-folds history |
| 19 | events-after-end-rejected | END is final |
| 20 | offline-pause-before-end-honored | a real offline pause survives a later END |
| 21 | claimed-at-out-of-bounds | clock-skew guard |
| 22 | invalid-permit-and-adjust-values | repeat PERMIT; ±3 h limit is inclusive |
| 23 | offline-pause-vs-admin-adjust | admin adjustment always survives |
