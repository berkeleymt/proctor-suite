Summary

These wireframes cover every screen in the Swire spec. Anything the spec doesn't describe follows the original swire app (berkeleymt/swire, SolidJS + Koa, 2024). The core loop stays the same as swire: a room has one timer plus some clarifications. Admins create and adjust them, and each room's projector shows a large countdown with the clarifications underneath. The spec adds:

  • a room dropdown on the login screen, replacing swire's namespace + username login
  • a room picker for sending clarifications, replacing swire's comma-separated text field
  • a proper deletion screen
  • a bathroom log for proctors and admins
  • a ContestDojo roster
  • a super-admin screen for passwords

  1. 1
    ChangedRoom dropdown

    Options are the rooms created on Admin · Timers, sorted alphabetically, with “Admin” pinned first. You can type to filter, which matters with 50+ rooms. This replaces swire's free-text namespace and username.

  2. 2
    From swireShared password

    There is one proctor password for every room and one admin password, the same model as swire's two env-var passwords. The spec sets both passwords for now. Super-admins can change them later.

  3. 3
    From swireDeep link

    Swire could prefill fields from the URL. The equivalent here is /login?room=evans10, which lets PMs send each proctor a link that preselects their room.

  1. 1
    DecisionStatus header + Start

    Swire let proctors press Start on their own room. The spec only gives timer control to admins. The wireframe shows Start disabled until an admin allows it. Alternative: remove it and have admins start every room. “Open display window” launches the display screen for dragging onto the projector.

  2. 2
    NewBathroom log

    Type an ID (the dropdown arrives with the roster) and press Mark out. The student moves to “Currently out” with a live timer. Returned moves them to the history list. Rows over about 10 minutes could be highlighted. Try the Returned buttons.

  3. 3
    DecisionChat with admins

    This was a core swire feature: per-room threads, admin broadcast, desktop notifications. The spec doesn't mention it. It's included here because it's the channel proctors use for problems during the test. Removing it is a one-panel change.

  4. 4
    NewProjector mirror

    Lets the proctor check what students see without looking up at the screen.

    NewPasswords

    Replaces swire's PROCTOR_PASSWORD / USER_PASSWORD env vars, so passwords can change without a redeploy. Optionally log out existing sessions after a change.

  2. 2
    DecisionAccess

    The spec says “a select few people” without saying how access works. Options are a separate super-admin password, or Google sign-in against an allow-list. The wireframe assumes the allow-list.

Open decisions

Can proctors start their own timer? No. The wireframe shows Start disabled until an admin allows it, and admins can also start rooms in bulk.
Keep Google Doc clarifications? Swire's per-room doc URL embedded a doc instead of native clarifications. It's kept as an optional field.
